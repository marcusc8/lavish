# Upstream PR material for kunchenguid/lavish-axi

Two independent changes we run locally as a patch on the built `dist/`. Upstream wants them in
`src/` (the repo builds `dist/` with esbuild), so port each from the reference diff, not by
copying the diff. NOT yet opened as PRs: Marcus decides when.

## PR 1 · Paste rich HTML as Markdown (composer + annotation card)
- Symptom: pasting from Google Docs (or any rich editor) into the `<textarea>` composer loses all
  structure because a textarea only accepts the text/plain clipboard flavor.
- Change: on `paste`, if the clipboard carries `text/html` with structure (heading, list, table,
  bold, link) and no image files, convert it with `html2md.js` (style-aware: Google Docs encodes
  bold as `font-weight:700` spans inside a `font-weight:normal` guid wrapper) and insert the
  Markdown at the caret; otherwise fall through to the existing image/text handling. Applied in
  the chrome composer (`chrome-client.js`) and the SDK annotation card (`src/…/sdk`).
- Tests to add: `html2md` unit tests over a captured Docs paste (headings, nested lists, table,
  link, plain text → "" so default paste is kept). Related upstream issue: #233 mentions the
  annotation-card textarea ergonomics.

## PR 2 · Keep sent annotations in the conversation log
- Symptom: only prompts tagged `message` are copied into `session.chat`; annotations, choices and
  exports live in `prompts` until `takeFeedback` clears them, so after Send to Agent they vanish
  from the panel and from disk.
- Change (server, `queuePrompts`): copy every accepted prompt into `chat` — `message` as today,
  everything else as `{role:"user", kind:"annotation", text:<summary>}` where summary =
  `[tag] “element text” — prompt` (or `on <tag> …` for element annotations). Change (chrome):
  `addChat(role, text, scroll, kind)` renders `kind === "annotation"` as a dashed full-width
  bubble labelled "You · sent annotation"; `syncChat` and the initial-chat bootstrap pass `kind`.
- Tests to add: queuePrompts writes one chat entry per prompt with the right kind; chat-sync
  re-render keeps them; existing tests that assert chat length for non-message prompts change.
- Related upstream issues: #228/#267/#296 (feedback delivery is destructive). This does not make
  delivery recoverable; it makes the human-readable record survive.

## PR 3 · Comments rail: private comments, editable queue, sent record, anchors + pins (added 2026-09-02)
- Symptom: queued prompts are opaque pills that cannot be edited; nothing lets the reviewer keep a
  note to themselves; sent annotations disappear from the panel until the agent polls (the server
  emits `chat-sync` only in `finishFeedbackDelivery`, never after `POST /api/:key/prompts`).
- Change (chrome, `rail.client.js` appended to chrome-client.js + `rail.css`): a Comments column with
  private / queued / sent cards, edit-in-place, Keep private ↔ Queue, Follow up / Resolve, a local
  bubble per annotation the moment Send succeeds, Home + Version history links. Private notes persist
  through a sidecar HTTP API (here the home page on :4388); upstream could persist them in state.json.
- Change (SDK): a "Keep private" card button posting `lavish:privateNote`; `window.lavish.privateNote()`;
  `lavish:resolveAnchors` → `lavish:anchorsResolved` (selector, then text-prefix re-anchoring, document
  order) and numbered pins that post `lavish:focusNote`.
- Related upstream issues: #206 (persistent edit history), #233 (conversation panel), #228/#267/#296.
- Reference: `patch-lavish.mjs` edits `client:review-rail`, `css:review-rail`, `sdk:*` (2026-09-02).
